## ⚠️ 危險等級定義(TTC 為主、距離為輔)

TTC(碰撞時間 = 距離 ÷ 接近速度)是主指標,speed-aware,對齊量產 FCW(Euro NCAP 約 TTC 2.4–2.7s 警示);
距離只當「再近一定危險」的保險底線。定義在 `hazard_warning.py::risk_of`(單一來源,滿足任一即成立):

| 等級 | 主:TTC(接近中) | 輔:距離底線 |
|---|---|---|
| 🔴 DANGER | TTC < **2.0s** | 或 < **5m** |
| 🟡 CAUTION | TTC < **4.0s** | 或 < **10m** |
| 🟢 SAFE | TTC ≥ 4s 或未接近 | 且 ≥ 10m |

可用 `--t_danger/--t_caution/--r_danger/--r_caution` 覆寫。

## 行人偵測:BEV 分割弱 → 改用「影像偵測 + 深度定位」(已解決)

BEV 分割器抓不到行人(人在 0.25m/px 的 BEV 只佔 2–3 px):像素 recall 0.013、實例 recall 0.163。
**改用 Path B —— 在相機影像上用 COCO 預訓練偵測器抓人(人又大又清楚)、再用深度定位到 BEV**
(`pedestrian_detect.py`),不用重訓。800 幀 hazard_town10_long 實測(可見區,252 個真人實例):

| 方法 | 行人 recall(實例級) |
|---|---|
| BEV 分割模型 | 0.163 |
| **影像偵測 + 深度** | **0.714(4.4×)** |

**混合設計(對齊真實 ADAS)**:大物體(車)用 BEV,小物體(人)用影像+深度。車輛仍走 BEV
(可見區 recall 0.591)。整合版 demo:`hazard_full.py`(車 BEV + 人影像+深度,同一 TTC/風險邏輯)。
剩餘 future work:行人的深度定位在部署時用模型深度(現用 GT 深度);更遠/遮擋的人仍會漏。

## 量化驗證:警示等級到底準不準(2026-09-11)

`eval_ttc.py` 把系統每一幀報出來的障礙物,對上 CARLA 自己知道的真值(actor 的相對位置與速度),
逐幀比對距離、TTC、以及**最後真正影響駕駛的那個東西——風險等級**。

Town10HD / 600 幀 / 20 台 NPC / `--seed 20260911`,只統計相機視野內的真值
(盲區看不到的東西沒偵測到是幾何問題,不是系統缺陷,另外列):

| 指標 | 數值 |
|---|---|
| 偵測到的可見真值 | **98.8%** |
| 風險等級一致率 | **88.8%** |
| 警告不足(真值該警告,系統說 SAFE) | 7.0% |
| 過度警告(真值 SAFE,系統卻警告) | **0.7%** |
| DANGER 被顯示成 SAFE | 3 / 58 |
| 距離誤差中位數 | **0.50 m** |
| TTC 誤差中位數 | 1.15 s |

混淆矩陣(列 = 真值,行 = 系統):

|  | SAFE | CAUTION | DANGER |
|---|---|---|---|
| **SAFE** | 341 | 4 | 0 |
| **CAUTION** | 37 | 115 | 16 |
| **DANGER** | 3 | 4 | 51 |

誠實面:TTC 誤差中位數 1.15 秒,相對 2.0 秒的 DANGER 門檻仍然偏大。原因是 `ttc_of()` 用
6 個帶雜訊的距離點做一次最小平方擬合,追蹤剛建立時斜率很不穩。**這正是設計上 TTC 之外還留
一條距離底線的理由**——距離的中位誤差只有 0.50 m,遠比 TTC 可靠,兩個條件滿足任一即警告。
改成加權最小平方或卡爾曼是已知的下一步。

## 警示穩定性:coast + 遲滯(2026-09-11 修正)

**症狀**:警告在閃。`results\DEMO_free_20260909_212801_events.csv` 裡,同一個行人在 1.2 秒內
RAISE / CLEAR 了五次,每次持續 0.1–0.2 秒;`DEMO_rear_approach_20260909_213914` 的後方警告
一樣以 0.1 秒為週期跳動。畫面上是閃爍的紅框,紀錄上是一堆假事件,而且讓 summary 的
「幾次警告」完全沒辦法引用。

**兩個根因**:

1. `Tracker.active()` 只回報「這一幀有配對到」的 track。追蹤器本來就設計成容許
   `max_miss=3` 幀的漏檢不刪除軌跡,但漏檢那一幀該障礙物就不會出現在警示層 → 該側等級掉回
   SAFE → 記一筆 CLEAR → 下一幀又 RAISE。**`max_miss` 的緩衝從來沒有接到會警告的那一半系統。**
2. `risk_of()` 無記憶。TTC 由 6 個距離點擬合而來,逐幀跳動零點幾秒,在一次**真實的**接近過程中
   就足以來回穿越 2.0 秒門檻好幾次。

**兩個修正**(`hazard_warning.py`):

| 機制 | 行為 |
|---|---|
| **coast** | 漏檢的 track 保留上一次偵測(標 `coasted`),用它的世界座標重新投影回當下 ego frame,撐到 `max_miss` 為止。歷史 `hist` 不補值——coast 不能餵假量測進 TTC 擬合。 |
| **`LevelHold` 遲滯** | **升級即時通過,降級要連續 0.5 秒才承認**(`--warn_hold`)。這是量產 FCW 的標準做法:一個會閃的警告等同壞掉的警告,駕駛會停止信任它。 |

**效果**(同 seed、同場景的成對量測,`--coast 0` vs `--coast 1`):

| 指標 | 改前 | 改後 |
|---|---|---|
| 偵測到的可見真值 | 89.2% | **98.8%** |
| 風險等級一致率 | 85.4% | **88.8%** |
| 警告不足 | 9.8% | **7.0%** |
| 過度警告 | 1.8% | **0.7%** |
| DANGER 被顯示成 SAFE | 3 / 58 | 3 / 58(不變) |
| 距離誤差中位數 | 0.48 m | 0.50 m |
| TTC 誤差中位數 | 1.42 s | **1.15 s** |

七項裡五項改善、一項持平(漏掉的 DANGER 一筆都沒有增加)、一項距離中位誤差多 0.02 m。
那 0.02 m 是 coast 的代價:漏檢那幾幀的位置是從上一次量測外推的,本來就會略差,換來的是
召回 89.2% → 98.8%。最大的一格是 CAUTION 召回 49.6% → 68.5%。

**關鍵性質:不會延遲任何一次真警告。** 離線 replay(15% 漏檢 + 0.45 m 距離雜訊)三個亂數種子,
第一次 CAUTION / DANGER 觸發的時間改前改後完全相同,而同一次接近產生的 RAISE 從 9 / 6 / 8 次
降到 1 / 1 / 3 次,持續不到 0.5 秒的假 CLEAR 全部歸零。**警告變穩,但沒有變慢。**

> 舊行為可用 `--warn_hold 0`(關遲滯)與 `Tracker(coast=False)` 復原,`eval_ttc.py --coast 0`
> 就是這樣做對照的。`metrics\ttc_eval_before.csv` 是改前的對照檔,
> `metrics\ttc_eval_20260809_pre_coast.csv` 是更早 8/9 的舊場景量測(NPC 相遇少、較寬鬆,
> 不可與上表直接比較)。

## 後車蛇行:徑向 TTC 結構性看不到的危險(2026-09-18)

`hazard_warning.ttc_of()` 擬合的是**距離**歷史。這對直直朝你開來的車是對的,對橫向擺動的車
則是**結構性失明**——不是準確度不夠,是那個量根本不包含橫向速度項。

合成驗證(後車維持 15 m、同速、±2 m 擺動、週期 3 秒,幅度足以兩度壓進自車車道):

| 量 | 整段 6 秒的表現 |
|---|---|
| 距離 | 15.00 ↔ 15.10 m |
| 接近率 | 始終在 ±0.21 m/s 內 |
| TTC | **無限大** |
| 最高風險等級 | **SAFE,一次都沒響** |

一台車在你後面兩度切進你的車道,系統全程不發一語。

### 方法:`trajectory_predict.py`

三個量,全部從追蹤器自己的世界座標歷史算出來,**輸入是真實偵測結果,沒有用到任何真值**:

| 量 | 意義 |
|---|---|
| **TTI**(time-to-intrusion) | 把目標**相對自車**的運動外推,預測幾秒後會進入自車車身框。這就是徑向 TTC 給不出的答案,因為它帶了 TTC 丟掉的橫向速度項 |
| **車道侵入時間** | 預測幾秒後會**跨進**自車車道(已經在車道內的車回傳無限大——跟在你後面的車沒有「剛剛做了什麼」) |
| **蛇行判定** | 用目標**自己的平均路徑**當基準,量垂直偏離的振盪 |

蛇行基準刻意用目標自身路徑而非自車:這樣**自車變換車道時不會誤判成後車在蛇行**。

三者分開回報。40 m 外狂蛇行的車不會撞到人(TTI 就該是無限大),但駕駛仍該知道——混在一起
不是狼來了就是沉默。**蛇行單獨只給 CAUTION,不給 DANGER。**

### A/B(同 seed、同場景、60 秒、Town10HD)

| | 後方警告時間占比 | **第一次後方警告** | 前方 |
|---|---|---|---|
| `--no_predict`(只有徑向 TTC) | 2.0% | **t = 56.5 s** | 3 CAUTION / 1 DANGER |
| 預測層開啟(預設) | **76.2%** | **t = 8.0 s** | 3 CAUTION / 1 DANGER |

**提早 48.5 秒。** 關掉預測時那唯一的後方警告,是最後蛇行車碰巧逼近到 10.9 m 才由距離門檻
觸發的——前面 56 秒完全靜默。前方數字兩邊完全相同,確認新機制沒有干擾既有行為。

事件記錄裡最值得引用的一列:

```
t_s   side  event  level    range_m  ttc_s    reason
8.0   rear  RAISE  CAUTION  23.01    42.55    WEAVE
```

**TTC 說 42.55 秒(等於沒事),預測層說要警告。**

## 危險車輛列管:把「駕駛行為」跟「當下幾何」分開

風險等級回答的是「現在這個場面有多危險」,每幀重算。那個形狀不適合「這個駕駛在亂開」——
後者是**車輛的屬性**,而蛇行車每個週期有兩個瞬間是直的,逐幀判斷剛好會在那時候把標記掉掉。

所以 `WatchList` 是**閂鎖式**的:連續 1.5 秒偵測到蛇行就列管,列管後**距離完全不列入考慮**。
30 m 外的蛇行車照樣掛著標記——它現在撞不到你,而**在它變成 8 m 之前就知道,正是重點**。

列管之後會**提前一級升級**:已知在亂開的車,預測到要侵入車道時直接給 DANGER,不像匿名車輛
只給 CAUTION。這是人類駕駛對「後面搖了二十秒那台車」的判斷。

實跑證據(240 秒,紅燈開著):

```
t_s   event    level    range_m  ttc_s   reason
34.3  UPGRADE  DANGER   25.09    (空)    WEAVE+LANE
56.5  UPGRADE  DANGER   10.81    1.60    (空)
```

**t=34.3 那列:車在 25 公尺外,徑向 TTC 是無限大,純粹因為它已被列管且預測會切進車道而升到
DANGER。** 舊邏輯要等到 56.5 秒、車逼到 10.8 公尺才第一次有反應。

### 三個 bug,同一個邏輯錯誤

2026-09-17 的一段 70 秒錄影裡,一台在 17 m 正確列管的車,30 秒後在 20 m 處變回普通的綠色
SAFE 方塊,而駕駛明明還在後面。拆開來是三件事,**但錯誤是同一個:把「量不到」當成「沒有」**。

| # | 症狀 | 修法 |
|---|---|---|
| 1 | 兩車一起停紅燈 → 停著的車量不到蛇行 → 被當成 15 秒的清白紀錄 → 放行 | `weave()` 回傳 **judgeable**;移動量不夠時**兩邊都不算** |
| 2 | 過路口或偵測斷超過 0.3 秒 → 軌跡死亡 → 同一台車回來是新 id → 紀錄被刪 | 列管車輛留下**幽靈**(最後世界座標+速度),新 id 先比對再當陌生車;追蹤器放寬到 1 秒,coast 期間改**死推算**而非凍結位置 |
| 3 | 車飄到 28–30 m → 擺幅量不到門檻 → 又被當成清白紀錄 → 30 秒後放行 | **振幅遲滯帶**:高於門檻=蛇行,低於 clear 門檻=真的開很直,**中間=不確定,兩邊都不算** |

修正過程的量化(240 秒同場景):

| 版本 | 列管時間 | 第一次列管 |
|---|---|---|
| 錄影裡那版 | 紅燈後永久消失 | — |
| + judgeable + 幽靈重識別 + 追蹤 1 秒 | 119.1 / 240 s (50%) | 72.9 s |
| + 振幅遲滯帶 | 192.0 / 240 s (80%) | 24.2 s |
| + 永不釋放 + 幽靈記憶 25 秒 | **215.7 / 240 s (90%)** | 24.3 s |

**該次 240 秒量測中沒有出現任何 `left the watch list`**:列管之後一路撐到結束,中間經過
紅燈、路口、軌跡死亡重建、車飄到 BEV 邊緣。

> **但這不是保證。** 2026-09-18 一次 40 秒的 smoke test(`--seed 20260918`、Town10HD)就出現
> 一次:track 0 在 9.1 s 列管,15.7 s 失去軌跡離開列管,17.1 s 由幽靈機制認回成 track 13
> ——中間空了 1.4 秒。列管時間 29.5 / 40.0 s(74%),低於該次 240 秒的 90%。
> **幽靈重識別是接得住的那一層,不是「絕不掉」**;正確的說法是「掉了會在一兩秒內接回來」,
> 不是「不會掉」。

### 為什麼用 SDLP 而不是峰對峰

蛇行的統計量換成 **SDLP-style**(橫向偏離的標準差)。SDLP(Standard Deviation of Lane
Position)是交通安全與人因工程領域評估橫向控制的**標準指標**,是酒駕、疲勞、藥物上路測試的
主要終點指標。

> **用詞要精確。** 文獻定義量的是**自車**相對**車道中心**、公分級儀器,並以約 2.4 cm 的增量
> 為有意義門檻(大致相當於 BAC 0.5 g/L 的損害)。本系統量的是**別台車**相對**它自己的平均
> 路徑**、來源是帶 0.5 m 雜訊的 BEV 質心——粗兩個數量級。應稱 **SDLP-style**,不可直接宣稱
> 是 SDLP。基準改成目標自身路徑是刻意的:自車不可靠地知道別台車的車道中心在哪。

選擇依據(七種操作 × 五個亂數種子,0.5 m 位置雜訊,各自掃到最佳門檻):

| 統計量 | 門檻 | 漏判 | **誤判** | 直線行駛的雜訊底線 | 大幅蛇行時 |
|---|---|---|---|---|---|
| 峰對峰 | 1.35 m | 1.5% | 4.3% | 0.51 m | 3.54 m |
| **SDLP-style** | **0.52 m** | 4.3% | **0.8%** | **0.13 m** | 1.13 m |

**誤判少五倍,漏判多一些。對這個架構而言這個取捨明確有利**:列管是閂鎖式的,漏掉幾幀完全
沒差(1.5 秒內累積夠就鎖上),而誤判在 `--watch_release 0` 之下**會永久掛著**。

峰對峰只看最大最小兩點,**單一離群值就能把它撐大**——最難的負樣本「單次變換車道」峰對峰
p90 衝到 1.50 m(已吃進蛇行範圍),SDLP 只有 0.44 m。

誤標實測:`rear_approach` 120 秒 **0 次**,`cut_in` 120 秒 **0 次**。

### 誠實限制

- **超過 30 公尺沒有任何輸入。** BEV 就是 ±30 m。實測 571 筆配對偵測:中位 21.8 m、
  p90 29.9 m、最遠 39.6 m(斜後方,方框對角可到 42 m)。正後方 30 公尺是絕對上限,
  而且原因是感測器配置不是演算法。
- **±1 m 的細微蛇行偵測不到。** 0.5 m 雜訊下兩種統計量都分不開(SDLP p10 0.37 m vs 難負
  樣本 p90 0.44 m)。本系統偵測的是「明顯在亂開」,不是「輕微受損」。
- **預測假設自車在預測期間直行。** 過彎時車道侵入測試會有誤報傾向;`--predict_hold` 的
  2 秒遲滯擋掉一部分。
- **`--watch_release 0`(預設)讓誤標永久保留。** 上述兩個場景測出 0 誤標,但那是兩個場景、
  各 120 秒。要恢復「將功贖罪」設 `--watch_release 30`。
- **同 seed 的 CARLA 長測會飄。** 同一個 seed 跑兩次,列管時間得到 201.0 s 和 228.9 s
  ——差 28 秒。`--seed` 固定得住生成點與 traffic manager,固定不住模擬本身。
  **單次長測的「列管時間」不足以比較兩個設定**;可複現的結論是離線掃描的誤判率,以及
  列管觸發時間(SDLP 10.2 / 11.1 s vs 峰對峰 24.3 s,兩次一致)。

## 上台工具鏈:三個修正 + 一個選單(2026-09-18 凌晨)

列管邏輯定案之後動的都是**舞台上的東西**——判斷邏輯一行沒改,改的是「錄下來的、印出來的、
看得到的」。

### `--record_secs`:錄影有上限,demo 沒有

`--record auto` 原本無上限。一次忘了關、整夜跑下去的 `rear_approach`
(`DEMO_rear_approach_20260911_091731`)寫出 **274,787 幀 / 27,479 模擬秒(7.6 小時)/ 40.0 GB**,
把 E: 塞爆;另一次彩排寫出 1.42 GB。兩支的 `_events.csv` 與 `_summary.json` 保留,mp4 已刪。

`--record_secs` 預設 **180 秒**,到時間**只停 writer,demo 繼續跑**:

```
recording capped at 180 s (1800 frames): ..\results\DEMO_*.mp4 -- the demo carries on
```

停 demo 是更糟的選項——簡報進行到一半被系統收走發言權。`--record_secs 0` 關掉上限。

同時補了一個開檔檢查:`cv2.VideoWriter` 開失敗時**不丟例外、`write()` 靜默無作用**,
畫面上一切正常,跑完才發現檔案是空的(`results\` 裡兩支 09-09 的 **44 bytes** mp4 就是這樣來的)。
現在開檔當下就印 `!! could not open the recording ... -- the demo carries on without it`。

### FLAGGED 記錄取錯了距離

列管觸發時印的那行公尺數,原本取的是**障礙物清單的第一個**,不是**被列管的那條 track**。
清單順序與列管對象無關,所以那個數字實際上是隨機的另一台車。改成從 `track_info[tid]` 取被
列管車自己的座標,並一起印 SDLP 與轉向次數,同時區分觸發來源是**蛇行證據**還是**幽靈重識別**:

```
[%6.1fs] FLAGGED track %d via {weave evidence | RE-ID}: {REAR|FRONT} %.1f m, SDLP %.2f m, %d reversals
```

### 蛇行幅度:量不到時保留上一個值

同一個「把量不到當成沒有」的家族(見上一節三個 bug)。列管車停紅燈時擺幅量到 ~0 m,HUD 把
數字清成 0,**一個還在生效的警告看起來像過期的**。現在只有**完全沒有列管車**時才歸零;有列管
車但這一幀量不到,保留上一次真的量得到的擺幅。

### `啟動DEMO.bat`:選單加 [7] 後車蛇行

桌面批次檔加了 `[7] 後車蛇行`,且**刻意不帶 `--peds`**——那個場景從頭到尾只有一台後車,而行人
偵測器吃掉約一半的每幀時間:

| | mean FPS | 畫面速度 |
|---|---|---|
| 帶 `--peds` | 6.62 | 0.66 倍 |
| **[7] 不帶** | **8.5 – 9.8** | **約 0.9 倍** |

`--peds` 因此設在 `PEDS=` 而不在 `COMMON=`,[6]([EXTRA] 清空)才真的關得掉。

> 批次檔存 **cp950 / Big5**,不是 UTF-8。cmd.exe 用主控台字碼頁解碼 .bat,存成 UTF-8 會讓中文
> 變亂碼,而且落單的前導位元組會吃掉後面那個引號——視窗在錯誤訊息看得清楚之前就關了。
> ASCII 副本 `啟動DEMO_EN.bat` 同步維護。

## 關鍵發現:變體 D 是危險警示的必要零件

原始模型預測在**盲區幻覺出障礙物**(尤其後方假車)。同一段行人接近場景:

| 偵測口徑 | 結果 |
|---|---|
| raw pred(信任盲區) | 31 DANGER / 5 CAUTION ← 盲區假警報 |
| **pred + 變體D(預設)** | **3 DANGER / 5 CAUTION** ← 假警報清除 |
| gt(真值上限) | 0 DANGER / 35 CAUTION |

**把主專案 README 的變體 D 洞見(盲區動態輸出是噪音)直接接進警示層,消掉 28 個假 DANGER。**
這是連結先前研究與新系統的技術賣點,簡報值得專門一頁。
