# 雙鏡頭 BEV 感知 → 實體小車實作指南(v2,已納入真車團隊稽核)

> 目的:把在 CARLA 模擬驗證過的「雙相機 BEV 語意感知 + 三維重建 + 危險警示」的**演算法與資料觀念**,提供給實體小車(D455 + ROS)團隊參考。
> 版本:**v2 / 2026-07-29**(依 `AUD-003` 整合稽核修訂,修正過度承諾、座標手性、GT 定義、盲區處理、即時邊界)。
> 原始碼:`E:\dualcam_project\src\`。主模型見第 7 節。

---

## 0. ⚠️ 定位與邊界(先讀,最重要)

**這份指南 + CARLA collector 是「合成 / legacy 參考」,不是真車正式契約。**

- ✅ 適合:CARLA 合成訓練、幾何回歸、**同場景 N=1 vs N=2 比較**、FOV 消融、未來 rear 的**軟體介面預演**、sim-to-real 觀念。
- ❌ **不能**取代真車既有的:ROS rosbag、來源 timestamp、strict manifest、D455 CameraInfo/TF、正式外參(A1)、fail-closed evaluator(B2)。
- ❌ CARLA 合成結果**不能**當作真車 accuracy、真 rear、盲區追蹤或 TTC 的正式競賽證據。

**正確的資料流(由真車格式「派生」legacy 格式,不是反過來):**
```text
真車 D455 / 未來 rear
  → ROS bag + source timestamps + CameraInfo/TF
  → strict manifest / validator
  → 正式真車評估(B2 / A1 / RF2O)
  → (選配)匯出 legacy CARLA-style folders 供舊工具使用

CARLA collector
  → synthetic / legacy CARLA-style dataset
  → 嚴格 CARLA-to-project adapter(見第 6 節)
  → synthetic regression / N=1 vs N=2 / training
```
→ **不要用本指南另寫一套較弱的真車 capture 去降級現有 rosbag 契約。**

## 3. CARLA collector 產生什麼(格式參考)

> ⚠️ 以下是 **CARLA 合成資料的格式**,可作 legacy interchange contract 參考;真車正式契約以 ROS 端為主。

### 3.1 資料夾結構
```
<dataset>/
├── front_rgb/  rear_rgb/            RGB(BGR PNG,%06d.png)
├── front_depth/ rear_depth/         深度(CARLA 打包格式,見 3.4)
├── bev_gt/                          ⭐ 六類 semantic BEV 標籤(單通道,值=類別)
├── bev_gt_color/                    上者上色版(僅視覺化)
├── bev_rgb/            (選配)       CARLA 上方 30m 空拍 RGB(參考,非模型輸入)
├── calibration.json                 相機內外參 + BEV 幾何 + 類別
├── poses.json                       每幀 ego [x,y,yaw](⚠️ 見 3.6 的不足)
└── preview.mp4
```
> ⚠️ **`bev_gt` / `bev_gt_color` / `bev_rgb` 是三種不同東西**:前者是六類語意 GT、中者是上色視覺化、後者是空拍 RGB 參考。不要混稱。

### 3.2 類別編碼(bev_gt 像素值)
| 值 | 類別 | | 值 | 類別 |
|--|--|--|--|--|
| 0 | background | | 3 | road |
| 1 | vehicle | | 4 | sidewalk |
| 2 | pedestrian | | 5 | **lane_marking** |

### 3.3 BEV 幾何(模型/評估寫死)
- 範圍 **±30 m**、解析度 **0.25 m/格**、尺寸 **240×240**、ego 中心
- 座標:`row` = 前向 x(遞減)、`col` = 右向 y(遞增)。正式使用要明寫 **frame / handedness / row-col 方向 / schema version**(見第 5 節)。

### 3.4 深度編碼(CARLA ≠ D455,務必分欄)
| | CARLA depth | D455 depth |
|---|---|---|
| 儲存 | 3-ch packed uint8 PNG | `16UC1` Z16 |
| 解碼 | `1000·(R+G·256+B·256²)/(256³−1)` 公尺(0–1000m) | device scale(約 mm→m) |
| 對齊 | 理想同 pose RGB/depth | **必須 depth-to-color alignment** |
| 缺值 | 理想無洞 | 有 0/洞/材質/光照/量程問題 |
- LSS 的 **2–42 m** learned-depth bins **不是** D455 硬體可靠距離,兩者分開報。

### 3.5 calibration.json(六類 + schema/version)
```json
{
  "schema_version": "1.0",
  "coordinate": { "frame": "ego", "handedness": "carla_y_right",
                  "bev_row": "x_forward_descending", "bev_col": "y_right_ascending" },
  "image": { "width": 640, "height": 360, "fov": 90 },
  "bev":   { "x_min": -30, "x_max": 30, "y_min": -30, "y_max": 30,
             "resolution": 0.25, "height": 240, "width": 240 },
  "classes": { "0":"background","1":"vehicle","2":"pedestrian",
               "3":"road","4":"sidewalk","5":"lane_marking" },
  "cameras": { "front": { "K":[[fx,0,cx],[0,fy,cy],[0,0,1]], "T_ego_cam":<4x4>,
                          "translation":[1.5,0,1.6], "rotation_deg":{"pitch":0,"yaw":0,"roll":0} },
               "rear":  { "...":"...", "translation":[-1.5,0,1.6], "rotation_deg":{"yaw":180} } }
}
```
> ⚠️ 舊 collector 產出的 calibration.json **只宣告 0–4 類、且無 handedness/version** → 正式使用前務必補成上面完整 schema(class 5 lane + 座標宣告 + version)。

### 3.6 poses.json 的不足(真車要加強)
CARLA 只存 `{"000000.png":[x,y,yaw]}`。**真車不能只存這樣**,至少要:
- source timestamp、frame、pose 來源(odometry/VIO)、covariance/quality
- 並在**影像 timestamp 上做 pose association / 內插**

## 4. 「換真車 = 幾乎不改程式」是**過度承諾** ❌ → 誠實清單

換 CARLA → 真車,**至少**要處理以下(現有真車專案已實作其中一部分,證明不是換資料夾就好):

| 項目 | 為什麼 |
|---|---|
| 深度 adapter | D455 Z16/mm、缺值/洞,與 CARLA packed 完全不同(3.4) |
| 相機驅動 / ROS capture | 從 rosbag 讀,不是檔案式截圖 |
| K/D + resize/crop K | 真相機內參 + 畸變;resize/crop 後 K 要重算 |
| 外參(A1) | 每相機自己的 `T_base_camera`,不能抄 CARLA(第 5 節) |
| **timestamp 同步** | 兩顆真相機無法用檔名 index 保證同步(第 5 節) |
| **座標手性** | CARLA y-右 vs ROS y-左 + 光學系(第 5 節) |
| 無效深度處理 | 0/洞/超量程 |
| **observed / unknown mask** | unknown=255 ≠ background(第 5 節) |
| 真 GT | 人工標註 + 量測 + reference(第 8 節) |
| odometry | 真 pose 來源(RF2O / VIO / wheel+IMU) |
| 即時延遲 / stale / drop / fail-closed | 競賽即時 Gate(第 9 節) |

**能直接沿用的**:BEV 幾何(±30m/0.25m/240²)、六類 schema、LSS 模型、評估公式、三維重建與警示的**演算法邏輯**——但都要接上上面正確的資料來源。

## 5. ⚠️ 座標、同步、observed mask(最容易錯,獨立成節)

### 5.1 座標手性(CARLA ≠ ROS ≠ 光學系,三種 frame)
```text
CARLA / model :  x 前, y 右, z 上
ROS base_link :  x 前, y 左, z 上
camera optical:  x 右, y 下, z 前
```
- **只能在唯一 adapter 邊界做一次** `y_ros = -y_carla`,下游不得再猜負號。
- **不能**只重用 `carla_transform_to_matrix()` 改個 translation 就填 ROS 外參——要明確定義 transform 方向、source/target frame、optical basis 轉換、handedness 轉換,並用**左/右/前的已知 marker 做回歸測試**(否則左右風險方向會鏡像)。
- 若把 CARLA `bev_gt` 拿去和 ROS 輸出比,GT 也要經**同一份版本化座標轉換**。

### 5.2 同步:六位數檔名**不是**同步證據
- CARLA 用 loop index 命名 → **只能說「設計上預期同 tick」,沒有留下同步證據**。
- 兩顆真實相機的正式 bundle 必須存:source timestamp、receive/storage timestamp、clock domain、front/rear skew、RGB/depth skew、clock offset/drift、drop/duplicate/one-use、reject/degraded 原因。
- 正式蒐集要**以 tick frame ID / timestamp 收齊所有 sensor,拒收 stale/future/duplicate,timeout 整幀 fail 不留半幀**。

### 5.3 observed / unknown mask(安全契約)
- CARLA `bev_gt` 把整張 ±30m(含 FOV 外、遮擋、超量程)都寫成語意類別,未標到的格子=background 0。
- **真車安全契約不同:`unknown/unobserved = 255`,且 unknown ≠ background ≠ safe。**
- 至少要另出:per-camera FOV mask、fused observed mask、occlusion(若可得)、`ignore=255`;並把 `full_map_gt` 與 `observable_gt` 分開評測。

## 9. 危險警示:定位與正式化(重要修正)

### 9.1 變體 D 是 fail-closed baseline,**不是**盲區預測
- 變體 D = 清掉盲區的 vehicle/pedestrian 以減假警報 → 是「**沒有可靠 motion model 時的保守 baseline**」。
- 企劃核心要的是「**進盲區後短期 coast / prediction**」(需 TTL、covariance、prediction age、re-observation)→ 這是 **future work**,變體 D 不等於它。
- 「DANGER 31→3」「盲區 54.7%」若無 machine-readable dataset/log 佐證,**不列正式成果**(目前是 CARLA 模擬統計)。

### 9.2 TTC / 距離門檻是 prototype 假設
- `DANGER=TTC<2s 或 <5m;CAUTION=TTC<4s 或 <10m` 只是起點,**不是安全門檻**。
- 正式值要配:實際低速範圍、煞停距離、capture/inference/output latency、位置/速度不確定度、固定 validation events、FP/FN + lead-time 報告。

### 9.3 離線 ≠ 即時 Gate
- 本套是「錄後桌機離線處理」→ 適合 replay/backup demo、圖表影片、dataset 比較、sim-to-real 研究。
- **不解除**競賽即時 Gate:`≥10 FPS`、capture-to-output p95 `≤150 ms`、live stale/drop/fail-closed、Jetson memory/thermal。

### 9.4 黑 rear 只能當 ablation
- 餵黑圖**不是**雙鏡頭,且容易把 unobserved 混成 background。現有 N=1 adapter 比黑 rear 誠實。
- 允許的說法:「Black rear 是 legacy model compatibility ablation,不是 rear observation,不列正式雙鏡結果。」

## 10. 評估公式(可保留,但需正式契約)

- IoU = TP/(TP+FP+FN);Precision = TP/(TP+FP);Recall = TP/(TP+FN);mIoU = 各類平均;F1 = 2PR/(P+R)
- 實例:距 GT < 門檻(車 3m/人 2.5m)命中;定位誤差 = 配對點平均距離
- 深度:MAE、RMSE、AbsRel、δ<1.25ᵏ(D455 與 learned depth 分欄)
- 警示:TTC = 距離÷接近速度;命中 = 同幀且距 <3m
> 正式化要求見第 7 節末(one-to-one matching、獨立 GT、event window…)。

## 11. 真車 GT 怎麼來(沒有免費完整 GT)

CARLA 從 map+actor registry 免費產六類 GT;**真車沒有**。真車 GT 用:量尺+固定 marker、獨立人工逐幀標註、已知路徑/場景、經驗證的 reference sensor。D455 depth 可輔助但**未驗證不能當絕對真值**。

> ⚠️ **現有 48 幀(B2-003 v3)不是完整 `bev_gt`**:它主要是 person/vehicle 影像 bbox + reviewer status(+ 選配 metric position),**不是** 240×240 六類 semantic BEV raster。要宣稱六類 semantic BEV accuracy,必須另建真正的 road/sidewalk/lane/vehicle/pedestrian raster GT。
